# Hello Lets Talk IITK (V2) — Technical Design & System Architecture
## Hybrid Graph-RAG, Automated Equation Extraction, and Grounded Local LLM (Llama 3.1 8B)

This document specifies the technical architecture, mathematical extraction engine, and multi-course implementation for **Hello Lets Talk IITK (V2)**. Building upon the dense vector search foundation established in V1, V2 introduces:
1. **Grounded Academic Generative QA** powered by local **Llama 3.1 8B** (hosted on local Ollama) with anti-repetition safeguards.
2. **First-Class Discrete Equation Modeling & Extraction Engine (`src/equation_extractor.py`)** combining verified curated catalogs with automated OCR/Unicode mathematical formula parsing.
3. **Hierarchical Multi-Course Knowledge Graphs** across **MTH441** (Regression & ANOVA), **CS771** (Machine Learning), and **EE602** (Estimation Theory textbook).
4. **Hybrid Graph-RAG Retrieval** unifying semantic vector similarity, sequential chunk adjacency (`NEXT_CHUNK`), and bidirectional equation graph traversal (`REFERENCES_EQUATION`, `HAS_EQUATION`).

## 2. In-Depth Architectural Solutions

### Point 1: LLM Text Generation with Llama 3.1 8B

#### A. Architecture Strategy: Specialized Grounded RAG Prompt (`src/generator.py`)
Rather than relying on an external agent wrapper or unbounded skill:
1. **Local Independence**: Hello Lets Talk IITK runs entirely offline via `http://localhost:11434/api/generate` with zero API dependencies.
2. **Strict Academic Grounding**: Enforces strict evidence containment. If a concept is not present in retrieved context, the model explicitly outputs: *"This concept is not covered in the provided lecture notes."*
3. **Exact Citation Enforcement**: Cites evidence with exact course and lecture brackets: `[MTH441 Lecture 03, Page 7]`, `[CS771 Lecture 10, Page 11]`, or `[EE602 Chapter 13, Page 440]`.
4. **Anti-Repetition & Generation Safeguards**:
   - `repeat_penalty: 1.15` and `repeat_last_n: 128` configured on the Ollama payload to prevent loop degeneration in greedy decoding.
   - Stop tokens configured: `<|eot_id|>`, `<|start_header_id|>`, `<|end_header_id|>`.
   - Post-processing response deduplication filter via `LLMGenerator.deduplicate_text()`.
   - Asynchronous button debouncing (cooldown) in `main.ipynb` to eliminate repeated click triggers.

### Point 2: Decoupled Equations & Automated Extraction Engine

#### A. Decoupling Rationale
PDF text extraction linearly flattens 2D mathematical layouts (fractions, matrices, multi-line optimizations), resulting in shredded formulas in raw body text. Hello Lets Talk IITK decouples equations into **First-Class Entities**:
- **Text Chunks**: Capture conceptual discussions, proofs, derivations, and intuitions.
- **Equation Entities**: Contain formal, clean LaTeX formulas, extracted mathematical variables, validity conditions, and exact page/lecture anchors.

#### B. Automated Equation Extraction Engine (`src/equation_extractor.py`)
The `EquationExtractor` dynamically detects, normalizes, and extracts equations from raw text chunks and textbook pages:
1. **Mathematical Density & Relation Heuristic**:
   - Requires mathematical relation operators (`=`, `\le`, `\ge`, `\approx`, `\propto`, `\in`, `\sim`, `\to`, `\arg\max`, `\arg\min`, `\min`, `\max`, `\sum`, `\int`, `\nabla`, `\partial`).
   - Identifies numbered equation tags `(X.Y)` (e.g., `(3.14)`, `(13.40)` in Steven M. Kay).
   - Validates mathematical density ratio (symbols and operators vs. natural language letters) to reject false positives.
2. **Unicode & OCR Normalization**:
   - Unicode NFKD decomposition maps mathematical alphanumeric characters (`𝒘`, `𝒙`, `𝒚`, `𝑏`, `𝑛`) to base ASCII letters while preserving bold/vector markers (`\mathbf{w}`, `\mathbf{x}_n`).
   - Translates math symbols: transposes `⊤, ᵀ` $\to$ `^\top`, sums `∑, ෍` $\to$ `\sum`, hats `෠` $\to$ `\hat`, inequalities `≤, ≥` $\to$ `\le, \ge`.
   - Cleans up OCR artifacts from scanned textbooks (e.g., Cyrillic character substitutions `д` $\to$ `\partial`, `==` $\to$ `=`).
3. **Automated Variable & Parameter Extraction**:
   - Parses LaTeX formulas for Greek parameters (`\alpha`, `\beta`, `\theta`, `\sigma`, `\mu`, `\lambda`, `\Sigma`), bold vectors (`\mathbf{w}`), and subscripts (`x_n`, `y_i`).
4. **Context-Aware Equation Naming**:
   - Uses regex pattern matching with strict word boundaries `\b` to infer names (e.g., "Support Vector Machine Formulation", "Neyman-Fisher Factorization Theorem (5.3)", "Kalman Filter Update").
5. **Smart Equation Deduplication (`src/graph_retriever.py`)**:
   - Eliminates duplicate formulas across retrieved chunks by `(page, normalized_latex)`.
   - Automatically prioritizes pristine curated catalog LaTeX over auto-extracted raw OCR variants.

#### C. Unique Identifier Taxonomy
Deterministic, human-readable IDs ensure cross-referencing between ChromaDB and the Knowledge Graph:
- **Course Node**: `COURSE_MTH441`, `COURSE_CS771`, `COURSE_EE602`
- **Lecture / Chapter Node**: `MTH441_L01`, `CS771_L10`, `EE602_Chapter13`
- **Topic Node**: `MTH441_L01_TOPIC_chi2`, `CS771_L10_TOPIC_soft_margin_svm`
- **Text Chunk Node**: `MTH441_L01_p09_txt_c02`, `CS771_L10_p11_txt_c01`, `EE602_ch13_p440_c01`
- **Curated Equation Node**: `MTH441_L01_eq_chi2_pdf`, `CS771_L10_eq_svm_soft_margin`, `EE602_CH13_eq_kalman_gain`
- **Auto-Extracted Equation Node**: `CS771_Lecture10_eq_auto_p11_1`, `EE602_Chapter13_eq_auto_p445_2`

#### D. Hierarchical Graph Schema (`src/graph_store.py`)
```
[Course: CS771]
   │ (CONTAINS_LECTURE)
   ▼
[Lecture: Lecture 10]
   ├── Metadata: {title: "SVMs & Kernels", prof: "Prof. Piyush Rai", source: "lecture10.pdf"}
   │ (COVERS_TOPIC)
   ▼
[Topic: Soft-Margin Support Vector Machine]
   ├── (HAS_EXPLANATION) ──► [Text Chunk: CS771_L10_p11_txt_01]
   │                              │ (REFERENCES_EQUATION)
   │                              ▼
   └── (HAS_EQUATION)    ──► [Equation: CS771_L10_eq_svm_soft_margin]
                                  ├── latex: "\min_{w, b} \frac{1}{2} \|w\|^2 + C \sum_{n=1}^N \max(0, 1 - y_n (w^\top x_n + b))"
                                  ├── variables: ["w", "b", "C", "y_n", "x_n"]
                                  └── conditions: "C > 0 controls tradeoff between margin and slack"
```

- Supports course filtering at retrieval time (`course_filter="CS771"`, `"EE602"`, or `"MTH441"`).

## 5. Verification & Acceptance Criteria

Hello Lets Talk IITK (V2) meets the following production criteria:
1. **Automated Mathematical Extraction**: The `EquationExtractor` parses lecture slides and dense textbooks, converts Unicode math characters and OCR artifacts into valid LaTeX, and extracts math variables without manual intervention.
2. **Comprehensive Equation Representation**: Over 950 discrete equation entities are linked across course graphs, guaranteeing that mathematical queries across all courses return structured LaTeX formulas.
3. **Strict Course-Filtered Retrieval**: Queries targeting specific courses (`-c CS771`, `-c EE602`, `-c MTH441`) only retrieve grounded evidence from that course's materials without cross-course contamination.
4. **Anti-Repetition LLM Generation**: Local Ollama responses are strictly guarded against repetitive text loops via stop tokens, sampling penalties (`repeat_penalty: 1.15`), and response deduplication.
5. **Exact Academic Citations**: The model outputs exact citations in `[<Course> <Lecture/Chapter> <Num>, Page <Num>]` format.
6. **100% Offline Capability**: Vector search, graph traversal, automated equation extraction, and Llama 3.1 8B generation run locally without external cloud dependencies.
